# 선물 우선 알고리즘

## 목적

블루 아카이브 제조에서 매 단계에 등장한 노드 중 선물 기대 가치가 가장 높은 노드를 선택한다.

제조는 항상 3차 노드까지 개방한다고 가정한다. 2차 및 3차 개방에 필요한 재료와 비용은 이미 지불하기로 결정한 매몰비용으로 보고, 노드 선택 점수에는 포함하지 않는다.

## 초기 가정

1. 제조는 항상 3차 노드까지 개방한다.
2. 개방에 필요한 재료는 충분하며 비용은 비교하지 않는다.
3. 제조 1회당 선물 기대 가치를 최대화한다.
4. 일반 선물의 가중치는 `1`이다.
5. 고급 선물의 가중치는 `3`이다.
6. 노드 이름이 아니라 실제 결과 확률과 수량으로 노드를 평가한다.
7. 선물 기대 가치가 같을 때만 가구 기대 수량을 비교한다.
8. 가구 기대 수량까지 같으면 무작위로 선택한다.
9. 서버와 제조 데이터 버전을 고정한다.
10. 확률표에 없는 결과나 확률 합계 오류를 임의로 보정하지 않는다.

## 데이터 구분

### 실행 입력

시행할 때마다 달라지는 값만 함수 입력으로 받는다.

```text
stage: CraftingStage
candidateNodeIds: List<NodeId>
```

- `stage`: 현재 제조 단계인 1차, 2차 또는 3차
- `candidateNodeIds`: 현재 화면에 등장한 노드 ID 목록

### 정적 참조 데이터

노드별 결과 확률표와 선물 가중치는 시행과 관계없이 고정된 데이터이므로 실행 입력에 포함하지 않는다. 알고리즘은 전역 상수 또는 읽기 전용 데이터 저장소를 통해 이를 참조한다.

```text
NORMAL_GIFT_WEIGHT = 1
ADVANCED_GIFT_WEIGHT = 3

CRAFTING_TABLE[stage][nodeId] = List<CraftingResult>
```

```text
CraftingResult:
    itemId: ItemId
    itemType: ItemType
    giftGrade: GiftGrade?
    probability: Number
    minQuantity: Number
    maxQuantity: Number
```

`CRAFTING_TABLE`은 SchaleDB의 제조 확률 데이터를 애플리케이션 내부 형식으로 변환한 읽기 전용 데이터다.

## 출력

알고리즘의 본질적인 출력은 추천 노드 ID 하나다.

```text
recommendedNodeId: NodeId
```

검증과 디버깅이 필요한 경우 다음 DTO를 사용할 수 있다.

```text
NodeDecision:
    recommendedNodeId: NodeId
    giftScore: Number
    furnitureScore: Number
    tiedNodeIds: List<NodeId>
    selectionReason: String
```

## 점수 정의

수량이 범위로 주어지면 균등 분포를 가정하고 산술평균을 기대 수량으로 사용한다.

```text
expectedQuantity = (minQuantity + maxQuantity) / 2
```

노드의 선물 기대 가치는 다음과 같다.

```text
giftScore(node)
    = SUM(
        result.probability
        * expectedQuantity(result)
        * giftWeight(result)
      ) FOR result IN giftResults(node)
```

동률 비교에 사용하는 가구 기대 수량은 다음과 같다.

```text
furnitureScore(node)
    = SUM(
        result.probability
        * expectedQuantity(result)
      ) FOR result IN furnitureResults(node)
```

## 수도코드

### 기대 수량

```text
FUNCTION GetExpectedQuantity(result):
    RETURN (result.minQuantity + result.maxQuantity) / 2
```

### 선물 가중치

```text
FUNCTION GetGiftWeight(result):
    IF result.giftGrade == Advanced:
        RETURN ADVANCED_GIFT_WEIGHT

    RETURN NORMAL_GIFT_WEIGHT
```

### 선물 기대 가치 계산

```text
FUNCTION CalculateGiftScore(stage, nodeId):
    score = 0
    results = CRAFTING_TABLE[stage][nodeId]

    FOR result IN results:
        IF result.itemType != Gift:
            CONTINUE

        expectedQuantity = GetExpectedQuantity(result)
        giftWeight = GetGiftWeight(result)

        score += result.probability
                 * expectedQuantity
                 * giftWeight

    RETURN score
```

### 가구 기대 수량 계산

```text
FUNCTION CalculateFurnitureScore(stage, nodeId):
    score = 0
    results = CRAFTING_TABLE[stage][nodeId]

    FOR result IN results:
        IF result.itemType != Furniture:
            CONTINUE

        expectedQuantity = GetExpectedQuantity(result)

        score += result.probability
                 * expectedQuantity

    RETURN score
```

### 추천 노드 선택

선물 기대 가치를 가장 먼저 비교하고, 동률일 때만 가구 기대 수량을 비교한다. 두 점수 모두 같으면 동률 후보 중 하나를 무작위로 선택한다.

부동소수점 오차 때문에 점수를 `==`로 직접 비교하지 않고 허용 오차를 이용한다.

```text
CONSTANT SCORE_EPSILON = 0.0000001

FUNCTION IsSameScore(left, right):
    RETURN ABS(left - right) <= SCORE_EPSILON


FUNCTION SelectBestNode(stage, candidateNodeIds):
    evaluations = EMPTY LIST

    FOR nodeId IN candidateNodeIds:
        evaluations.ADD({
            nodeId: nodeId,
            giftScore: CalculateGiftScore(stage, nodeId),
            furnitureScore: CalculateFurnitureScore(stage, nodeId)
        })

    highestGiftScore = MAX(
        evaluation.giftScore
        FOR evaluation IN evaluations
    )

    giftCandidates = FILTER evaluations
        WHERE IsSameScore(
            evaluation.giftScore,
            highestGiftScore
        )

    IF COUNT(giftCandidates) == 1:
        RETURN giftCandidates[0].nodeId

    highestFurnitureScore = MAX(
        evaluation.furnitureScore
        FOR evaluation IN giftCandidates
    )

    furnitureCandidates = FILTER giftCandidates
        WHERE IsSameScore(
            evaluation.furnitureScore,
            highestFurnitureScore
        )

    RETURN RANDOM_CHOICE(furnitureCandidates).nodeId
```

### 디버깅 DTO 반환

운영 로직은 `NodeId`만 반환하고, 점수 근거가 필요할 때 다음 함수를 별도로 사용할 수 있다.

```text
FUNCTION SelectBestNodeWithDebugInfo(stage, candidateNodeIds):
    evaluations = EvaluateNodes(stage, candidateNodeIds)
    giftCandidates = FindHighestGiftCandidates(evaluations)
    furnitureCandidates = FindHighestFurnitureCandidates(giftCandidates)
    selected = RANDOM_CHOICE(furnitureCandidates)

    IF COUNT(giftCandidates) == 1:
        reason = "선물 기대 가치가 가장 높음"
    ELSE IF COUNT(furnitureCandidates) == 1:
        reason = "선물 기대 가치 동률로 가구 기대 수량 우선"
    ELSE:
        reason = "선물과 가구 점수가 모두 같아 무작위 선택"

    RETURN NodeDecision(
        recommendedNodeId = selected.nodeId,
        giftScore = selected.giftScore,
        furnitureScore = selected.furnitureScore,
        tiedNodeIds = MAP(
            furnitureCandidates,
            candidate -> candidate.nodeId
        ),
        selectionReason = reason
    )
```

## 단계별 사용

2차와 3차 후보는 앞 단계 선택 이후에 공개되므로 제조 전체를 한 번에 입력받지 않고 단계마다 같은 함수를 호출한다.

```text
stage1NodeId = SelectBestNode(First, stage1CandidateNodeIds)
// 1차 노드를 선택하고 2차 후보가 공개된다.

stage2NodeId = SelectBestNode(Second, stage2CandidateNodeIds)
// 2차 노드를 선택하고 3차 후보가 공개된다.

stage3NodeId = SelectBestNode(Third, stage3CandidateNodeIds)
```

현재 수도코드는 각 단계에서 관측된 선택지만 평가하는 탐욕 알고리즘이다. 특정 노드 선택이 다음 단계의 노드 출현 분포에 영향을 준다는 조건부 확률 데이터가 확보되면, 이후 단계의 기대 가치까지 포함하는 동적 계획법으로 확장할 수 있다.
